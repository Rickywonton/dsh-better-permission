# better-permit v0.6.1

> 修掉审批弹窗里那块纯白按钮；把「AI 解释」从复述命令改成**后果分析 + 危险等级**，
> 认不出用途时也给结论，不再出现「无法判断」。

- 版本：`0.6.1`（`better-permit` / `better-permit-ui` 同步）
- 上一个版本：`0.6.0`
- 详细变更：[`CHANGELOG.md`](CHANGELOG.md) · 版本档案：[`docs/RELEASES.md`](docs/RELEASES.md)

## 这一版解决什么

0.6.0 的解释像在念源代码：把命令原文和风险原因拼在一起，等于把弹窗上已有的信息又念一遍；
遇到规则表不认识的动词，还会给出「无法识别」这种没结论的话。另外主按钮在这套主题下渲染成一块
纯白的空按钮。

## 改了什么

### 1. 解释改成后果分析

`lib/explain.js` 重写，只讲两件事：**最坏会失去什么**、**为什么来问你**。

> 会删除或覆盖已有内容，删掉的东西通常无法恢复。当前档位「工作区内 · AI 判定」只自动放行到
> 「写入」这一档，所以来问你。

- 完全不引用命令与参数（弹窗里本来就有命令块）。
- 每个风险等级一句后果：只读 / 写入 / 删除覆盖 / 系统层 / 工作区外 / 对外发布 / 无法识别。
- 评审模型的提示词收紧到 **≤40 字**，明确禁止复述命令、引用代码、讲规则。

### 2. 危险程度不再「无法判断」

`explain` 新增 `level`（`safe` / `caution` / `danger`）与 `risk` 字段：

```json
{ "sentence": "…", "source": "local", "level": "danger",
  "risk": { "key": "system", "label": "系统层", "hint": "会触碰系统配置" } }
```

- `unknown` 一律归为 `danger`，文案明说「按较高风险对待，建议先确认它要动什么」。
- 弹窗把 `level` 渲染成彩色徽标（安全 / 需留意 / 高风险），紧挨解释来源标签。

### 3. 纯白按钮

`primaryButton` 从「品牌色底 + `#fff` 字」改成「raised 表面 + 品牌色边框/文字」。
品牌 token 与白色不保证有对比度，token 缺失时更会渲染成白底白字；新写法在浅色与深色主题下都可读。

## 兼容性

- 新增字段：`explain.level`、`explain.risk`；旧字段 `sentence` / `local` / `source` 语义不变。
- 行为变化：解释变短、不再包含命令原文——若你的脚本从 `sentence` 里提取命令，请改用 `/detail` 的
  `command` 字段。
- `unknown` 风险在界面上显示为「高风险」，不再显示「无法识别」。

## English summary

v0.6.1 fixes a blank white primary button in the approval dialog and rewrites the explanation: instead
of echoing the command it now states the consequence of that risk grade and why the tier is asking,
and every explanation carries a `level` (`safe` / `caution` / `danger`) rendered as a coloured badge —
`unknown` grades are always `danger`, so the dialog never reads as "cannot judge". The reviewer prompt
is capped at 40 characters and forbidden from restating the command. 198 host checks, 72 UI checks.
