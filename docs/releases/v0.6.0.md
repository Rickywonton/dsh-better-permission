# better-permit v0.6.0

> 让每一次「自动放行」都说得清、留得下：审批弹窗用中文解释这一步在做什么、最坏什么后果；
> 每轮对话结束时，把这一轮替你做掉的审批汇总成一条报告写回对话。

- 版本：`0.6.0`（`better-permit` / `better-permit-ui` 同步）
- 上一个版本：`0.5.0`
- 仓库：[`better-permit`](README.md) · 详细变更：[`CHANGELOG.md`](CHANGELOG.md) · 版本记录：[`docs/RELEASES.md`](docs/RELEASES.md)

## 这一版解决什么

0.5.0 让档位会自己判断、会问模型、会在你久等时暂缓。但两件事仍然别扭：

1. 弹窗只给命令和风险等级，看不懂的命令（`Remove-Item`、`reg add`、某个构建脚本）还得自己去猜后果。
2. 自动放行越多，越说不清「这一轮它到底替我做主了什么」。

0.6.0 把判定结果翻译成人话，并把它记成账。

## 亮点

### 1. 审批弹窗里的中文解释

`GET /better-permit/approval/detail` 新增 `explain` 字段：

```json
{
  "sentence": "这一步会递归删除系统驱动目录，可能让设备无法启动。",
  "local": "这一步要执行的命令是「Remove-Item C:/Windows/system32/drivers -Recurse」……",
  "source": "model"
}
```

- **配了评审模型** → `source: "model"`，模型写一句（≤60 字，只讲「在做什么 + 最坏后果」，6 秒上限）。
- **没配 / 超时 / 报错 / 答空** → `source: "local"`，用命令、工作目录、风险等级、风险说明和
  「档位为什么没放行它」拼出的确定性句子。
- 解释按 `callId` 缓存（最多 32 条），弹窗反复取数不会重复问模型。

界面里渲染成独立一段，标签区分「评审模型的解释」和「这一步在做什么」。

### 2. 每轮自动放行报告

每轮对话收尾（`agent/turn-stopping`）时，把这一轮本插件返回过 `allowed-once` 的调用按
「签名 + 风险」归类，写成一条消息追加进对话：

```
本轮自动放行 3 次审批（未打扰你）：
· dir ×2 — 风险「只读」，由档位上限放行
· pnpm install ×1 — 风险「写入」，由本对话规则放行
```

- 放行人分四类：档位上限 / 本对话规则 / 受信路径 / 评审模型。
- 空轮不写；写失败只记日志（`category: 'report-failed'`），不影响会话。
- 报告是 `developer` 消息：聊天里渲染成一条注入行，但 `dsh-llm` 会把 developer 消息从模型可见
  消息里过滤掉，所以它**不占模型上下文**，纯粹是给你看的账。
- 设置页「每轮自动放行报告」卡片保留最近 10 条；`GET /better-permit/approval/panel` 的
  `reports` 字段同样可读。

### 3. 文档双语

三份 README 顶部都有 `[中文](README.md) | [English](README.en.md)`，英文版与中文版结构一一对应
（章节、表格、代码块、数字、路径都对齐）。

### 4. 修复

- 没有命令签名的调用（例如 `plugin_manager` 的插件动作）在报告里曾经渲染成空行
  （`·  ×3`）；现在回落到「工具名 + 动作」，显示为 `plugin_manager list_bundles ×1`。

## 下载

| 文件 | 大小 | 用法 |
| --- | --- | --- |
| `better-permit-0.6.0.zip` | ≈87 KB | **推荐**。源码形式：解压后得到 `better-permit/` 与 `better-permit-ui/` 两个目录，各装一次即可（无需构建） |
| `better-permit-0.6.0.tgz` | ≈51 KB | `npm pack` 产物，Host 半区，供 npm / pnpm 场景使用 |
| `better-permit-ui-0.6.0.tgz` | ≈19 KB | `npm pack` 产物，浏览器半区 |

zip 里带 `INSTALL.md` 与 `LICENSE`，两个包都不含 `postinstall`、不含第三方依赖。

```
plugin_manager  action: install_bundle  target: <解压路径>\better-permit
plugin_manager  action: install_bundle  target: <解压路径>\better-permit-ui
```

装完刷新 http://127.0.0.1:3079。

## 从 0.5.0 升级

```pwsh
plugin_manager set_bundle  target: better-permit      enabled: false
plugin_manager set_bundle  target: better-permit      enabled: true
plugin_manager set_bundle  target: better-permit-ui   enabled: false
plugin_manager set_bundle  target: better-permit-ui   enabled: true
```

然后刷新 http://127.0.0.1:3079（客户端 bundle 不会自动热更）。

- 无需改配置：档位、`ai.*`、`holdMs`、`trustedCommands` 全部向后兼容。
- 想看到「模型写的那句解释」，在插件 config 里配 `ai.baseUrl` / `ai.model` / `ai.apiKeyEnv`；
  面板「评审模型」卡片上有「测试连接」。
- 报告默认开启，没有开关；不想看可以忽略那条注入行（它不进入模型上下文）。

## 兼容性与限制

- 新增文件：`lib/explain.js`、`lib/reports.js`；新增面板数据 `reports`；`/detail` 新增 `explain`。
- 行为变化：每轮结束可能多一条 `developer/message`（仅当本轮有自动放行）。
- 解释依赖命令文本与风险启发式，不是沙箱；真正的约束仍是沙箱模式与档位上限。
- `danger-full-access` 提权永远不由模型决定。

## English summary

better-permit v0.6.0 makes every automated approval explainable and auditable: each approval dialog
now carries a plain-Chinese sentence about what the step does and what could go wrong (written by
your own reviewer model when configured, otherwise composed deterministically from the command, the
risk grade and the reason the tier refused it), and each turn ends by appending one report of the
approvals the plugin answered for you — grouped by command class, with counts, risk and who approved
(tier ceiling / conversation rule / trusted path / reviewer model). Reports are `developer` messages,
so they render in the transcript but never enter the model's context. Docs are now bilingual
(`README.md` / `README.en.md`). 191 host checks, 71 UI checks.
