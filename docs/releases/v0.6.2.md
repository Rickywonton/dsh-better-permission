# better-permit v0.6.2

> 受信文件夹现在对**所有档位**都生效——包括 AI 判定、高危才问、自动放行。
> 之前它只写在「受信放行」档的门里，切到更宽的档位就完全失效了。

- 版本：`0.6.2`（`better-permit` / `better-permit-ui` 同步）
- 上一个版本：`0.6.1`
- 详细变更：[`CHANGELOG.md`](CHANGELOG.md) · 版本档案：[`docs/RELEASES.md`](docs/RELEASES.md)

## 这一版解决什么

「受信文件夹」看起来是个全局概念：你在面板里加了一个目录，期望之后这个目录里的操作都被放行。
实际上受信判定只写在 `escalate` 门的 `trusted` 分支里，而 AI 判定 / 高危才问 / 自动放行这三档的门
都是 `all`——它们只看 `maxRisk` 上限，从来没查过受信清单。结果就是：同一个目录，在「受信放行」档里
畅通，切到「AI 判定」档后要么弹窗、要么被送去问评审模型，等于受信清单只在一档里有意义。

## 改了什么

### 1. 受信判定移到档位上限之前

`lib/engine.js` 在算完风险之后先做一次受信判定，`trustedHit` 命中就绕过该档位的 `maxRisk`：

| 档位 | 之前 | 现在 |
| --- | --- | --- |
| 写入自动 / 受信放行 | 提权门 `all` / `trusted`，受信只在后者生效 | 受信目录内的操作直接放行 |
| AI 判定 | 超上限一律送评审模型 | 受信命中直接放行，**不再调用评审模型** |
| 高危才问 | 超上限（工作区外 / 完全访问）一律问 | 受信路径直接放行 |
| 自动放行 | 本来就全放行 | 行为不变 |

### 2. 三条安全边界一条没松

1. **硬停机优先**：受信覆盖排在 `alwaysAsk` 之后。AI 与高危才问档的系统层、对外发布仍然一定问你。
2. **删除要具体到路径**：`destructive` 只有 `scope === 'path'`（受信的就是被删路径）才算覆盖，
   所以「命令跑在受信目录里」不会放行 `rm -rf *`。
3. **完全访问提权例外**：AI 判定档的 `danger-full-access` 门是 `off`（永远问你）；只有受信放行与
   高危才问档，才会自动放行「目标路径本身受信」的完全访问提权。

`checkTrust()` / `checkInstallTarget()` 的返回值新增 `scope`（`path` / `workdir` / `command` / `package`），
引擎据此区分「受信的是路径」和「只是在这个目录里跑」。

### 3. 文案跟上

面板顶部说明、`/tiers` 的状态行、以及给模型看的 prompt context 都改成「受信文件夹在所有档位生效」，
并写清完全访问的例外——否则模型会以为某些档位下受信目录仍需申请。

## 兼容性

- 配置：向后兼容，无需迁移。
- 行为变化：受信目录里的操作在更宽的档位也会自动放行。若你曾因为「受信在 AI 档不生效」而把档位
  调宽（例如长期停在自动放行），现在可以调回 AI 判定或高危才问。
- 新增字段：`checkTrust()` 返回的 `scope`（插件内部使用，不出现在 HTTP 响应里）。

## English summary

v0.6.2 makes trusted folders count on **every** tier. Until now the trust check only lived in the
`trusted` escalation gate, while the AI, high-risk-only and autopilot tiers use the `all` gate and never
consulted the trust lists at all — so a folder trusted in the panel was silently ignored on exactly the
tiers people use to reduce interruptions. The decision engine now computes the trust verdict before the
tier ceiling: a trusted hit skips `maxRisk` and, on the AI tier, never reaches the reviewer model.
Three boundaries are unchanged and covered by tests: the tier's `alwaysAsk` list still wins, a delete is
only covered when the deleted path itself is trusted (a trusted working directory does not vouch for
`rm -rf`), and a full-access widening still asks on the AI tier. 209 host checks, 72 UI checks.
